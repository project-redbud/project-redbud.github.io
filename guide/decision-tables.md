# 决策表

决策表让角色按一组有序规则选择行动，例如低生命时治疗、敌人聚集时释放范围技能、最后使用普攻。规则只表达行动意图，仍须满足当前状态、决策点、配额、资源、目标与射程限制。

## 何时使用

当前版本支持 `beforeDecision`，在角色普通 AI 决策前评估。多行动回合每次需要新决策时重新匹配，不是整回合只查一次。

| 优先顺序 | 处理 |
|---|---|
| 1 | 宿主已明确选择的动作 |
| 2 | AI 确认已有有效协同申请 |
| 3 | 当前行动角色绑定的决策表 |
| 4 | 表未命中时的回退：默认 AI，或结束回合 |

决策表通过 AI 控制器接入。手动角色的普通行动不会自动按表执行；`EnableAI = false` 时不评估角色策略。AI 协作方使用自己的表向当前行动者提交原地申请，与当前行动者是否为手动玩家无关。手动控制的协作方由宿主显式提交，不被 AI 代选；协同不能移动。

## 怎样匹配

规则的 `priority` 越大越先尝试，同优先级按配置顺序。禁用的规则跳过。每条规则先尝试合法目标、站位及施法方案，再对同一方案检查条件；条件成立且动作可执行才算命中。

无法执行时继续尝试后面的规则。例如，治疗规则满足生命条件，但技能冷却、资源不足或没有合法目标，就继续考虑范围攻击或普攻。规则表不会强行执行非法动作，也不会绕过宿主筛选的目标或禁用的动作类别。

全部未命中时，`defaultAI` 使用当前 AI 模式继续决策，`endTurn` 则结束回合。空表配合 `defaultAI` 可用于保留默认行为。显式 `endTurn` 动作是有效决策，表示主动结束，而非“继续匹配”。

## 目标、移动与位置

| 配置 | 含义 |
|---|---|
| `self` | 自身 |
| `ally` | 友方，包含自身；实际还要满足技能的目标条件 |
| `enemy` | 敌方 |
| `lowestHpRatio` / `highestHpRatio` | 按生命比例排序 |
| `nearest` | 按距离排序 |
| `movement: never` | 禁止移动 |
| `movement: ifNeeded` | 允许按方案选择位置 |
| `movement: required` | 必须移动才能执行 |
| `positionPreference: current` | 优先移动成本低的方案 |
| `positionPreference: coverage` | 优先覆盖更多合法目标，其次移动成本与风险 |
| `positionPreference: safe` | 优先低风险，其次覆盖数与移动成本 |

绑定名只在当前规则内有效。范围条件 `plan.targetCount` 统计选中方案的合法角色覆盖数，不是格子数，也不是地图上的敌人总数。

无地图时，`distance`、`plan.risk` 条件不匹配，强制移动、接近和撤退动作不可执行；允许按需移动的技能仍可原地规划。协同行动始终禁止移动，表内的 `endTurn` 表示不提交协同申请。

## 执行前重验

规划完成后，队列会在移动前、动作开始后及询问后重新检查。若目标死亡、资源变化或施法位置失效，当前尝试会跳过失效规则并按有限重试继续决策。已经成功的移动不会回滚，后续规划从角色真实位置执行。

安全位置使用当前可见敌人的移动与射程估算威胁数量。风险为 0 也不保证吟唱绝对安全：它不会预测隐藏效果、敌人策略或队友保护。候选预算属于近似搜索，不能保证每个局面都找到最优解。
