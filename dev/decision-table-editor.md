# 可视化决策表编辑器

Testing-v3 的 `webui` 提供 Core 决策表编辑器。启动包含前端的 Testing-v3 WebAPI 后，从首页主菜单或侧栏最后一项“决策表编辑器”进入，路径为 `/decisiontable`。该入口位于 `webui`，`webui-solo` 使用单人对局界面。

编辑器生成协议版本 1 的 `beforeDecision` JSON。配置导出后由宿主加载并绑定角色，页面不会自动修改运行中的对局。规则含义见 [决策表](../guide/decision-tables.md)，接入代码见 [编写决策表](./decision-tables.md)。

## 编排规则

1. 设置策略 ID（`module:name`）和未命中时的 `defaultAI` / `endTurn` 回退。
2. 添加规则，设置优先级和启用状态；可以复制、删除，并用箭头调整配置顺序。高优先级先匹配，同级按配置顺序，页面会预览启用规则的实际匹配顺序。
3. 选择自身、友方（含自身）或敌方，按最低 / 最高生命比例、最近距离或自身选择器筛选目标，设置目标绑定名。
4. 配置普攻、技能、物品、接近、撤离或结束回合，以及移动策略、位置偏好、方案绑定和风险上限。
5. 添加条件，通过 AND / OR / NOT 组合内置条件，或填写宿主注册的扩展标识与 JSON 参数。

目标绑定供动作和目标条件引用，方案绑定供 `plan.*` 条件引用。重命名会同步当前规则的对应内置引用；两类绑定即使同名也分别处理。绑定不能跨规则使用。

`movement: never` 严格原地行动，`ifNeeded` 允许按需移动，`required` 要求移动。`current`、`coverage`、`safe` 分别偏好低移动成本、覆盖与安全站位，均按实际位置计算风险；协同申请始终受 Core 的原地限制。

规则最多 256 条；条件根节点深度为 0，最多嵌套 16 级，每个 `all` / `any` 最多 64 个直接子条件。编辑器会定位无效绑定、未知字段和配置边界错误，完整条件及动作字段见 [配置指南](./decision-tables.md#动作字段)。

## 模组目录与模板

技能和物品目录来自当前服务的 `/api/gamedata`，可按名称或 ID 搜索。离线时可以手动输入 ID，空表和攻击模板也可继续使用。治疗模板从目录中查找“回复弹”并使用其实际 ID，加载前需取得对应目录。

资源存在不代表角色已学会或当前可以使用。冷却、DP、配额、资源、目标与位置仍由运行时检查，最终执行前再次重验。

自定义条件和动作可编辑 `module:name` 标识及参数对象。使用配置的宿主必须注册相应扩展；校验服务只能识别它实际注册的扩展。

## 草稿与 JSON

有效草稿自动保存在当前站点的浏览器本机存储，刷新可恢复。配置或参数 JSON 无效时保留上一份有效草稿，不覆盖它。不同站点地址的草稿独立。

撤销、重做保留最多 50 次编辑历史，模板载入和导入替换也可撤销；刷新后重新记录历史。

可粘贴 JSON 或选择文件导入，失败时保留当前配置。页面支持实时预览、复制和下载。浏览器导入会拒绝超出 JavaScript 安全整数范围（±9,007,199,254,740,991）的大整数及溢出数值，避免 ID 或参数被静默舍入；Core 自身的资源 ID 类型仍是 `long`。

## 检查与接入

| 阶段 | 检查内容 | 完成后的含义 |
|---|---|---|
| 本地检查 | 结构、字段、绑定、边界与参数 JSON | 可继续编辑和导出 |
| Core 编译校验 | 服务端 Parser、Compiler.Validate 和 Compile；可选当前模组资源目录 | 当前校验服务能够编译该配置 |
| 宿主加载与绑定 | Loader 注册策略，并按角色 `DecisionTableId` 绑定 | 角色后续 AI 决策可以使用策略 |

修改配置或资源检查选项后，已有 Core 校验结果会标为过期。服务不可达时仍可本地编辑和导出。下载成功不表示已通过 Core 校验，也不表示已经绑定到角色。

导出后，按 [文件导出与加载](./decision-tables.md#文件导出与加载)调用 `DecisionTableLoader.Load`，设置角色的 `DecisionTableId`，再调用 `Bind`。角色反序列化后也需要重新加载并绑定。

### WebAPI 校验接口

以下接口由 Testing-v3 WebAPI 提供：`POST /api/decision-tables/validate`。

```json
{
  "json": "{\"id\":\"example:empty\",\"rules\":[]}",
  "checkResources": true
}
```

成功响应示例：

```json
{
  "valid": true,
  "diagnostics": []
}
```

格式或语义校验失败时返回 `valid: false` 和带 `path`、`message`、`code` 的诊断，校验结果仍使用 HTTP 200。`checkResources` 默认 true，检查当前模组的技能和物品 ID；false 时仍检查 Core 结构、绑定与扩展。接口只校验，不注册策略、不绑定角色，也不写入服务端配置文件。

运行时还应关注预算截断和执行失效，见 [运行诊断](../api/DecisionTable.md#运行诊断)与 [AI 规划](./ai-planning.md)。
